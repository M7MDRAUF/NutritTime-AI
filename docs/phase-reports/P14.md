The screens that capture the data every safety decision depends on. Single-threaded by design.

of them was a silent, delayed erasure of the user's allergy list.**

## What verification found

### CRITICAL — the app wrote a value its own schema rejects, and the next launch erased the allergies

`repository.set` deliberately does not re-validate: "a value that fails its own schema is a
typed-caller bug, not a storage condition." **P14 made that caller untyped in practice** — the screen
dispatched on every keystroke and the store held anything.

The sequence needs no deep link and no P18:

1. Onboarding → dietary setup. Tap the peanut chip.
2. Type 31 comma-separated dislikes. **There was no dislikes rule**, so the form was valid, Save
   completed onboarding, and the app ran normally.
3. The queue persisted 31 items against `userPreferencesSchema`'s `.max(30)`.
4. Next launch: `safeParse` fails, `classifyEntry` quarantines the **whole entry**, the live key is
   removed, and the store is created from `DEFAULT_PREFERENCES` — `allergies: []`.
5. `onboarding.completed` lives on a separate key and survived, so the phase was `app` and Home
   painted meals filtered by nothing.

**Nothing told the user.** `entryStatus === 'recovered'` was surfaced nowhere.

A single keystroke of `08:` in a meal-time field reproduced it identically — and
`onboarding.spec.ts` already performed that write without noticing.

Fixed in four places, because one would not have been enough:

- **The reducer cannot produce an unstorable value.** Dislikes are capped at `MAX_DISLIKES`; a meal
  time that `parseClockTime` cannot read is refused rather than stored; `preferences/replaced`
  sanitises too, because that is the path a restored backup takes.
- **The form has a dislikes rule**, so the user is told rather than silently truncated.
- **The screen holds the half-typed text in its own draft state**, so the user still types freely
  and sees their own characters while only times reach the store.
- **`recovered` is surfaced** on both Home and the setup form. A reset allergy list is the one reset
  a user must be told about: the app looks normal and nothing is filtering.

### CRITICAL — a partially typed meal time crashed the render

`parseClockTime` throws `RangeError` on anything but zero-padded `HH:mm` — verified for `'08:'`,
`''`, `'7:00'`, `'08:0'`. `useRecommendations` called `mealPeriodForDate` in an unguarded `useMemo`,
during render, over a store value the user was mid-typing. With the form open in the `app` phase Home
is mounted beneath it, so **one keystroke crashed Home** — and there is no error boundary anywhere in
the app, so React unmounted the tree. The thrown message also quotes the user's typed value.

The store fix above is the real repair. `useRecommendations` also catches and falls back to `snack`,
because the store is not the only way a value can arrive — a migration, a restored backup, a future
import — and a crash is the worst available response. **R-50 records the general hazard**: an error
boundary around the navigator is a P22 task.

### The `.js` rule and the NUL byte

`preferencesState.ts` used a **raw U+0000** as the allergy-fingerprint separator. `file` reported the
source as `data`; ripgrep's `files_with_matches` mode **omits binary files**, so a search for
`allergiesRevision` returned the two files that read it and **not the file that defines it**. The
most safety-critical module in the project was invisible to every content search, while prettier and
eslint passed because it parses as one character. Both occurrences are now `'�'`, with the
reason for the separator written at the site. Recorded as **R-49**.

### Four tests that could not fail, and one I could not make trustworthy

- **`createStore` had no test at all** — the factory five stores share. TSD §6.3 says of its three
  invariants "each of which the tests check"; nothing anywhere failed a write while a store was
  mounted, so `saveError`, `saveBlocked`, `retrySave`, the coalescing queue and the
  "stop draining on failure" rule were unexercised, and `DietarySetupScreen` rendered a whole
  user-facing surface for them that no test had rendered. Six tests now cover it.
- **The reload e2e spec asserted nothing about the choices.** Its docstring claimed FR-003's
  "preferences survive restarts"; the body checked only that onboarding was not shown again — the
  `onboarding` key. Dropping every `preferences` write left it green. It now reads the stored
  allergy back, from both the form and `localStorage`.
- **`preferences/replaced` violated TSD §6.3's third invariant**, always allocating, so an identical
  replacement triggered a write. Now reference-preserving.
- **The allergy error surface was unreachable.** Every write path canonicalises, so
  `validateAllergies` can never fail through the screen. The rendered error is removed — dead UI
  reads as coverage — and the validator stays, because it guards the paths that do not come through
  the screen. The reason is written where the surface was.
- **I deleted a test I could not make trustworthy.** The "used outside its Provider" assertion:
  calling the hook directly gives React's own "Invalid hook call"; rendering inside
  `StorageProvider` puts the throw in a later async commit that React 19 reports as an unhandled
  rejection; rendering it bare did not rethrow either, while the structurally identical test in
  `ThemeProvider.dom.test.tsx` does. A test that passes for a reason I cannot explain is worse than
  no test, so the gap is recorded in place instead.

### Two defects the end-to-end run found that no dom test could

1. **The boot phase was derived from the hydration snapshot** — read once at boot, never updated. So
   dispatching `onboarding/completed` moved the store and left the phase behind: **Save did nothing
   visible until a restart.** The phase now comes from the live store.
2. **`DietarySetup` exists in both the `onboarding` and the `app` phase**, so React Navigation kept
   the route across the phase change: the phase advanced, storage said `{"completed": true}`, the
   screen set swapped — **and the user still sat on the form they had just finished.** Distinct
   `navigationKey`s make them different screens. Recorded as **X-30**: TSD §6.1's "the phase
   determines which screens exist, not a redirect on top of a mounted tree" failing from the other
   direction.

I diagnosed the second by dumping `localStorage` mid-journey rather than guessing — the key _was_
written, which ruled out the dispatch and pointed at navigation state. **`bootPhase.dom.test.tsx`**
is the fast half of the guard; no dom test had rendered the phase, because the screen suites mount a
screen directly.

**And Splash never rendered at all.** `StorageProvider` got no `fallback`, so nothing rendered during
hydration and the navigator holding `Splash` is inside it — `hydrating` was reachable only through
the font gate, while PRD §8.1 opens "Splash hydrates persisted state". FR-001's guarantee was
_stronger_ than specified rather than weaker, but the screen the document names never appeared.

## Judgements recorded rather than quietly decided

`design-system/DECISIONS.md` §7.5 carries **S-41 … S-48**. The load-bearing ones:

- **S-41 — `allergiesRevision`.** FR-003 needs a screen to detect an allergy change, and comparing
  arrays cannot: `['peanut']` and a fresh `['peanut']` are different objects with equal contents.
  A counter that moves only when the canonical set differs makes the invalidation a property of the
  store rather than a convention each screen has to remember.
- **S-42 — an unknown allergy term is dropped.** `conflictingAllergens` matches such a term only as
  a literal ingredient-name substring (R-30), so keeping it would make the UI look as though it had
  accepted a protection the domain cannot provide. **Only safe because the form offers the canonical
  list rather than a text box** — the pair is the containment, and dropping alone would be data loss.
- **S-43 — when validation fires.** Errors are computed every render and filtered by whether the
  field was visited; once shown, a correction forgives on the next keystroke; Save un-filters
  everything. `08:` is not a wrong time, it is an unfinished one.
- **S-45 — Save is not what persists.** Every change writes immediately; Save only completes
  onboarding. A user who force-quits halfway keeps what they chose, which for an allergy list is the
  behaviour that matters.

## Known limitations carried forward

- **R-50 — no error boundary anywhere.** One reachable instance was found and fixed twice over; the
  hazard is general and owned by P22.
- **R-51 — a hung storage write latches the queue.** No timeout, because no document gives a figure
  and inventing one here would be inventing a threshold. Matters at P22 on a quota-exhausted origin.
- **R-46 — `react-hooks/exhaustive-deps` is not registered**, so dependency arrays are reviewed by
  hand. P15's frozen-clock defect is what a hand review getting it wrong looks like.
- **R-47 / R-48** — React Native declares no `group` accessibility role, and `AppText` cannot render
  a status colour. Both are handled honestly rather than faked with a cast.
- **X-31 — the meal-time ordering rule forbids a night-shift profile the domain supports**, and no
  document asks for the rule. Kept for now, because removing it trades a blocked configuration for a
  silently broken one; raised for the user.
