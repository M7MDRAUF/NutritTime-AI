## What the independent verification changed

14 findings, 1 Major. The ones that mattered:

1. **Major - invented API.** `mealPeriodWindows()` and `MealPeriodWindow` were exported from
   `meal-period.ts` and re-exported from the package barrel. TSD 4.3 defines neither, nothing
   consumed them, and their only caller was their own test. Removed. This was scope creep in a
   module written here, not by an agent.
2. **`formatMoney` contradicted its own comment.** The comment claimed integer division;
   JavaScript has none, and `/` is IEEE-754. No runtime defect - truncation cannot cross an
   integer boundary inside the safe-integer range - but the comment now says what is actually
   true and names the distinction from the `toFixed` form TSD 4.2 forbids.
3. **`formatMoney` garbled negatives.** `-5` rendered as `"$0.-5"`, because `Math.trunc(-0.05)`
   is `-0` and `padStart` does not pad a negative remainder. `money()` cannot produce such a
   value, but `Money` is a plain interface and an object literal can. Now renders `-$0.05`,
   with a test.
4. **Two test amounts sat outside the contract schema range.** `money(123456)` is $1234.56
   against the `moneySchema` cap of 100,000 cents. The values were brought inside the range.
   The underlying divergence is recorded below.
5. **A test rationale was false.** The 09:29 case was commented "breakfast is nearer by two";
   in fact lunch's offset is -91, one minute past its opening edge, so lunch is not a candidate
   at all. The assertion passed for the wrong reason. Comment corrected to say what it tests.
6. **TSD 4.3's literal `00:00` vector was missing.** The tests covered 00:15, 01:30 and 01:31
   with a 23:30 anchor, but not midnight itself. Added.

## A measured negative result

I added `env: { TZ: 'America/New_York' }` to the Vitest config so a `getUTCHours()`
implementation of `mealPeriodForDate` could not pass unnoticed on a UTC runner - then measured
whether it worked. **It does not on this host:** `process.env.TZ` reads unset and the offset
stays at the machine's own (UTC-7) either way, because Node on Windows ignores a runtime `TZ`
change. The setting was removed rather than kept as a guarantee it does not provide. The test
now asserts local-versus-UTC divergence only where the host offset is non-zero, and states the
limitation in place. **P26 should pin `TZ` at the CI runner level, where it does take effect.**

## Deviations and divergences recorded

1. **`money()` and `moneySchema` disagree about a valid `Money`.** The constructor enforces
   integer and non-negative; the schema additionally caps at 100,000 cents. TSD 4.2 states no
   maximum, so no bound was invented here - but P05 and P07 construct prices through `money()`,
   and a value that passes the constructor can still fail the schema at the boundary. R-14.
2. **`tokenizeSegments` does not treat `.` or a newline as a segment separator.** The class
   matches TSD 4.1 exactly, so this is spec-conformant - but ingredient strings in P04 and P07
   commonly contain both, and P04's allergen suppressors depend on segment boundaries. Flagged
   forward rather than changed unilaterally. R-15.
3. **`formatMoney` tests cannot distinguish the required technique from the forbidden one.**
   All five vectors produce identical output under `(cents / 100).toFixed(2)`. The padding case
   is the one that would catch a naive template implementation.
