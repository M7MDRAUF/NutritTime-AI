## 1. R-69 — the build that compiled for nine phases and had never run

Reproduced verbatim before anything was changed: `build:server` exits 0, then
`node apps/server/dist/index.js` dies with
`ERR_MODULE_NOT_FOUND: Cannot find module '…/packages/contracts/src/core.js'`. Node 24 strips types
so `index.ts` loads; it dies on the `.js` → `.ts` gap one level deeper. **The gate's build step had
only ever proved compilation, not runnability** — the exact distinction this phase draws for itself.

### The acceptance, run on the real tree

```
npm run build:server            -> exit 0
node apps/server/dist/index.js  -> listening, Ollama down
GET /health                     -> HTTP 200
{"status":"ok","catalogVersion":"1.0.0","mealCount":60}
```

`mealCount` **60**. The boot line reports `aiEnabled: true` while Ollama is stopped, which is correct
and is the point of TSD's rule that `/health` **probes no dependency**: a health check that failed
because Ollama was down would tell the operator the wrong thing.

### The shape, and why nothing else broke

Three `packages/*/tsconfig.build.json`, one `build` script each, a root `build:packages` sequenced
**explicitly** because the graph is contracts → domain → catalog and `npm --workspaces run`
guarantees no topological order, and a dependency-free `stagePackages.mjs` that copies each package's
`dist` into `apps/server/dist/node_modules/@nutritime/*` with a minimal generated manifest.

**No `main`, `types`, `module` or `exports` field moved.** That is the whole design:
`apps/server/dist/node_modules/` is the **first** directory Node checks from `dist/*.js` and the
**only** resolution scope no other tool looks in — so the five consumers that must keep reading
TypeScript source are untouched: the seven `tsc` projects, Vitest, Metro, `tsx watch`, and the real
`tsx` subprocess `boot.integration.test.ts` spawns. **`tsx` and production `node` are the same
resolver with the same export conditions**, so no field could have sent one to `dist` and the other
to `src`.

| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |

## 2. T-26-01 — the Run URL is unobtainable, and that is the finding

`git remote -v` is **empty**. This is a private, solo, local-only project with no forge behind it, so
no push can happen, no Actions run can exist, and no run URL exists to record.

**Nothing was fabricated.** No remote was added and no local Actions runner was installed — `act` is
not in TSD §2.1, so reaching for it would have been a stop condition, not a convenience. The honest
close: the workflow is authored, parsed and structurally validated (`bash -n` 13/13), and **every
step executed locally in the workflow's own order** with its real output recorded.

A fabricated run URL would be the single most dishonest artefact this project could produce, which is
why the row reads Partial rather than Completed.

## 3. R-59 — "fail loudly", chosen because the alternative is unavailable

`npm run check`'s test total is machine-specific: **7 USDA tests hide behind a gitignored archive**
read from `USDA_DATASET_PATH`, which lives outside the repository by design. The Plan's own
requirement is that CI either provides the archive or **fails loudly when it is absent** — silently
running 7 fewer tests is the one option that must not ship.

"Provide the archive" is **unavailable**: it is uncommittable, and with no forge there is no cache,
artifact store or registry to fetch it from. So: fail loudly, in two places, because the workflow can
only make **its own** runs loud while TSD §2.4 puts the gate at `npm run check`.

| state                                | expectation      | measured                                                                    |
| ------------------------------------ | ---------------- | --------------------------------------------------------------------------- |
| archive present (this machine)       | run              | **7 passed**, exit 0                                                        |
| no archive, `CI` unset — a developer | skip, unaffected | **7 skipped**, exit 0                                                       |
| no archive, `CI=1` — a runner        | **run and fail** | **7 failed, exit 1**, each naming `USDA_DATASET_PATH` and TSD §7.4's reason |

The workflow step itself was exercised in five states: present → 0, absent → 1, `optional` → 0,
bad-path → 1, both-unset → 1. The failure message names the **variable**, never a path — and this
machine _has_ the archive, which is precisely why the drift was invisible here.

## 6. X-46 — a divergence this phase introduced deliberately, and disclosed

**`npm run dev` never started the Expo server on Windows.** `&` is a **sequential** separator under
`cmd.exe`, which is the shell npm uses (`script-shell` unset) — so SDD §2.3's documented
one-command procedure was unmet on this project's own platform, and `docs/RUNBOOK.md` would have
inherited the same false instruction.

Measured in an out-of-tree replica with a byte-identical copy of the new script: the old shape
printed only `server up at …` and `dev:mobile` **never ran**; the new one printed both, **11 ms
apart**.

**Why it survived nine phases:** under Git Bash `&` backgrounds correctly and the documented command
works. Anyone verifying §2.3 from a POSIX shell on this machine would have seen it pass — the same
shape as §6.1k, a line that cannot execute in the environment you measured it in.

**Authority order settles the fix and the disclosure.** SDD §2.3 promises behaviour; TSD §2.4
specifies a literal that does not deliver it. SDD outranks TSD, so the code is the defect and
`scripts/dev.mjs` uses Node's own `spawn` — **no dependency**, since `concurrently` and `npm-run-all`
would both be TSD §2.1 stop conditions. **No document was edited.** X-46 records all four ways TSD
§2.4's script block now differs from the tree; three predate this window (`typecheck` lists four
projects where seven run, no `build:server`, no `format`) and the fourth is this one.
