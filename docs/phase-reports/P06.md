## The defect class the verification exposed

Six defects, and four of them were **one mistake made four times**: the classifier extracted a
signal and the resolver silently dropped it. The result is the worst failure this module can have -
a fluent, confident, correctly-cited sentence answering a question nobody asked. Containment cannot
catch it: every id is cited, every figure is permitted, no denied claim fires. The sentence is simply
about something else.

1. **CRITICAL - a listing discarded the criterion and answered with the unfiltered set.**
   `"what vegan options do I have?"` against a catalog of meat dishes returned
   `"Here are 3 meals: Steak Dinner, Beef Burger, Chicken Pie."` The classifier matched `vegan`
   correctly; `decide` threw it away. This is PRD 7.4's own Listing example.
2. **CRITICAL - a count discarded an explicit field.** `"how many calories are in these"` returned
   `"3 meals match your preferences."` - byte-identical to the answer for
   `"how many xyzzy are in these"`. This is exactly the failure `THRESHOLD_TERMS` was added to
   prevent, but only the numeric spelling was guarded; the bare field spelling walked through.
3. **MAJOR - criterion ambiguity was computed and then not used.** `only(criteria)` returned its
   `ambiguous` flag and the disjunction omitted it, so `"how many vegan breakfast meals"` collapsed
   to no criterion and counted everything.
4. **MAJOR - `matchesCriterion` tested the literal diet tag** instead of TSD 4.5 satisfaction, so a
   `['vegan']` meal did not count as vegetarian and no meal counted as halal. It contradicted the
   module every other part of the system consults.

**The fix is one rule, applied everywhere: no extracted signal may be discarded.** Either a field, a
direction and a criterion are all used, or the question is refused. `decide` now returns a
discriminated union carrying the criterion on every variant, and every kind filters by it.

## Other corrections

5. **MAJOR - a listing's figure was the retrieval cap presented as a total.** `"Here are 5 meals"`
   against a sixty-meal catalog reads as "you have five". Reworded to `"Here are 5 of your vegan
meals: ..."`, so the number is visibly a count of what is shown.
6. **MINOR - the listing-beats-superlative precedence rule was mine and it was wrong.**
   `"list the meals by price, cheapest first"` inferred a single winner, answering a narrower
   question than the one asked and silently moving the scope from context to eligible. **The rule is
   removed.** A listing carrying a field is now an ORDERING, which uses both signals and keeps the
   opener's scope.
7. **A total carrying a direction, and a listing carrying a bare direction, now refuse** rather than
   ignore the signal.
8. **Comparatives reached nothing.** `"which is cheaper"`, `"which is faster"`, `"what is the
priciest"` all classified as `no-intent`. Added.
9. **`total` was ungrammatical for five of six fields.** "The total calories ... is" does not agree.
   Reworded to `"The meals shown come to 1700 kcal in total."`, which reads correctly for all six.
10. **`figures` duplicated entries** when a single candidate produced the same number twice.
11. **A vacuous test.** `'how many calories are in these'` asserted only that something resolved -
    it would have passed with the `calories` lexicon entry deleted, because defect 2 made it
    resolve to the same sentence as a nonsense question. Now asserts the statement.
12. **Plan section 20's stated vector was not run.** It asks for a superlative over a **60-meal**
    eligible set; the shipped test used three. Added at the size the system actually runs at.
13. **Token claiming was completely unpinned.** Removing it changes no outcome with the present
    tables, because every sub-phrase resolves to the same value as its parent. A behavioural test
    cannot observe it, so the test now pins the precondition it depends on - longest-first
    compilation of every table.
14. **A dairy gap found by the P07 catalog review, fixed here.** A real meal listed _Fromage Frais_
    and inference reported no milk at all. `fromage`, `paneer`, `halloumi` and `quark` added.

## Judgements recorded rather than quietly decided

- **PRD 7.4 offers "How many are under $10?" but TSD 4.9 defines no numeric criterion.** Left alone,
  that question answers with the size of the whole eligible set. `THRESHOLD_TERMS` makes it refuse.
  The verifier was asked to second-guess this and agreed refusing is correct. The durable fix is a
  specified threshold criterion in TSD 4.9. **X-15.**
- **PRD 7.4 lists Capability ("What can you do?") as a shape; TSD 4.9 declares no capability kind.**
  Mapped to `greeting`, the closest declared outcome - but a greeting and a capability question now
  return byte-identical outcomes, so a route cannot give them different copy. **R-22.**
- **`RetrievalPreferences` is defined in-module** because TSD 4.8 names it without declaring it,
  exactly as 4.6 does for `RecommendationPreferences`.
- **`matchedDislikedIngredients` is newly exported from `scoring.ts`** so retrieval and scoring share
  one implementation, for the reason TSD 4.7 gives for relevance having one implementation and two
  callers.

## Safety: what was checked and held

Forty adversarial probes through `retrieveChatMeals` could not get an allergen-conflicting meal into
`eligible` or `context`: declared tags in four spellings, untagged ingredients across fourteen
allergens with no declared tag at all, the wheat-to-gluten closure in both directions, the
non-taxonomy literal path, and the suppressors. Steps 1-3 run before any ranking by construction.

Figure containment was probed the way it matters: every numeric run in `statement` extracted with
TSD 5.7's own regex and checked for coverage by `figures` union the digits in the named meals, across
11 question shapes by 10 price magnitudes, digit-bearing meal names, and zero values. **Zero misses.**

## Known limitations carried forward

- **A criterion listing is context-scoped, so it can omit an eligible meal that did not rank.**
  "What vegetarian options do I have?" lists the vegetarian meals among the five retrieved, not all
  of them. The sentence is true - "here are 2 of your vegetarian meals" - but incomplete. Changing
  it means amending TSD 4.9's scope table. **R-20.**
- **A superlative's citation is routinely outside `scope.context`,** which is the scope rule working
  correctly. If P21 implements PRD FR-015's citation check against the retrieved five rather than
  against `namedMeals`, every correct superlative whose winner falls outside the top five will be
  discarded. **R-21 - a loaded gun pointed at P21.**
- **`total` sums any of the six fields,** where TSD 4.9 says `sumMoney`. Summing money uses
  `sumMoney`; the others are non-negative integers by schema so a plain sum is exact.
