## What the independent verification changed - two silent false negatives

The verifier was told to hunt false negatives specifically. It found two, both of which
returned an empty result where a real allergen was present:

1. **A user allergic to "nuts" was never warned about peanuts.** `normalizeAllergen('nuts')`
   resolved to a single canonical allergen (`tree-nut`), and the ambiguous-match path in
   `conflictingAllergens` is gated on that resolution being `null`. So path 1 failed (the meal
   carries `peanut`, not `tree-nut`), path 2 failed (whole-token matching, and the tokens were
   claimed), and path 3 never ran. `"nuts"` is the likeliest thing a user types, and peanut is
   the most common life-threatening food allergy. **Fixed** by listing `nut` under both peanut
   and tree-nut, which makes the term ambiguous and re-opens the catch-all path.

2. **A user allergic to "seafood" was never warned about prawns.** The term inferred nothing,
   and path 3 tests what a term implies - so it is inert exactly when it is needed, for an
   umbrella word outside the taxonomy. **Fixed** by adding `seafood` to both the fish and
   shellfish token lists, and `mollusc`/`mollusk` to shellfish.

Both now have named regression tests.

## Other corrections

3. **`gram flour` collided with a unit word.** "500 grams flour" singularises to
   `["500","gram","flour"]`; the rule claimed both tokens and the wheat vanished - and
   `unclaimedTokens` blanked `flour`, so the literal path died too. The rule is removed;
   `chickpea flour` covers the same ingredient without the collision.
4. **Four catalog staples carried wheat with no token.** `sausage` (UK sausages are bound with
   rusk), `dough`, `suet` (retail suet is flour-coated) and `asafoetida` (compounded hing is
   cut with wheat flour) were all invisible. Added, each leaning to the false-positive side.
   `chocolate` was added to milk on the same reasoning.
5. **False positives hiding staples.** `cream of tartar` and `butter beans` reported milk; a
   `dairy-free` or `nut-free` label reported the allergen it disclaims, and a record declaring
   `"nut free"` would have gained a tree-nut tag. Suppressors added for all of them.
6. **The "longest first" ordering was a guarantee the code does not implement.** `claimPhrases`
   applies every rule at every position and unions both the consumption mask and the tag set,
   so the result is order-independent and the sort is a readability aid. The comment claimed
   best-match semantics a future editor would have relied on. Corrected to say what is true.
7. **`unmetDietRequirement` returned a live reference** to the policy table. Now copies.

## Deviations and judgements recorded

- **`gluten free bread` reports wheat and gluten.** The suppressor claims the two words it
  names; `bread` is a separate token. A safe loaf is hidden. Suppressing the whole segment
  instead would silence soy in `"gluten free soy sauce"` - a false negative, and the failure
  this module exists to prevent. Fixing it properly needs a rule that removes specific tags
  rather than claiming tokens, which TSD 4.4 does not describe, so it is recorded rather than
  invented. A test asserts the current behaviour and the reason.
- **Lexicon entries are a judgement call in both directions.** `sausage` will wrongly flag an
  Italian sausage that is genuinely gluten-free. That is the tolerable error: a hidden safe
  meal, never an exposed unsafe one.

## Known limitations carried forward

- **A misspelled declared tag contributes nothing canonical.** `allergenTags` is
  `z.array(z.string())`, so a record hand-tagged `"treenut"` resolves to no canonical allergen
  and is rescued only if the ingredient list independently betrays the nut. T-07-04 is a hand
  review, so a typo is the expected failure mode there. **P07 should validate declared tags
  against the taxonomy at seed time.** R-16.
- **`singularize` mangles `-ches` stems ending in `e`:** `quiches` becomes `quich`, which
  reaches no token. Low catalog impact (both usually appear singular), but it is a plural
  folding gap. R-17.
- **`conflictingAllergens` recomputes inference several times per allergy.** Correctness is
  unaffected - every function is pure - but it is the hot path for every recommendation and
  every retrieval.
