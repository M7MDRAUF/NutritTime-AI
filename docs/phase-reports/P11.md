## The contrast test found a real bug

`content.inverse` over the image scrim measured **2.62:1 in dark**. The cause is structural rather
than a wrong hex: the dark scheme's inverse tone is _dark_, because its inverse surface is light -
and a photograph is not a surface the theme picks, so that pairing must not flip with the scheme.

Fixed by adding `content.onImage`, light in **both** maps and the only non-flipping role in the
system, rather than by relaxing the threshold. Recorded as S-11.

## T-11-06's "dark is authored" demonstrated rather than asserted

Deleting `darkColors.status.danger` and running `tsc` produces
`error TS2741: Property 'danger' is missing`. The dark map satisfies the same interface by
construction, so it cannot silently fall back to a derived value - which is what a programmatic
inversion of the light palette would have been, and it produces unreadable greys.

## Two enforcement gaps this phase closed

1. **`packages/design-system` was the one package in `packages/` that Rule 3 did not cover**, so
   nothing stopped a token module importing from `apps/`. Nothing did, but it was unenforced
   (A-11-04). The Rule 3 file list now names it, **and the rule was probed**: a deliberate
   `import { createApp } from '../../../../apps/server/src/app.js'` is reported
   `packages must not import from apps`. P01's lesson was that an unproven lint rule is an
   unenforced one.
2. **Prettier was rewriting a generated artifact.** Formatting `MASTER.md` lowercased three hex
   literals inside CSS fences (`#EA580C` -> `#ea580c`). That file is kept as EVIDENCE of what the
   generator recommended, so its text has to survive verbatim. `design-system/MASTER.md` and
   `design-system/pages/` are now prettier-ignored, exactly as `meals.json` already is;
   `DECISIONS.md` is authored prose and stays formatted.
