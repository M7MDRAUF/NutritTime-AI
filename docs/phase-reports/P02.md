## What the independent verification changed

The verifier returned 11 findings (5 Major). The four that mattered:

1. **The all-or-nothing rule was one-directional.** It constrained `unavailable` but never the
   converse, so a catalog record could ship all-null nutrition with **no origin and no reason** -
   FR-006's "never a guess" degrading to "null with no explanation". `origin: 'user'` was wholly
   unconstrained, so a record could claim values with no serving count to divide by. The rule is
   now exhaustive across all three origins **and** ties `nutritionProvenance.origin` to the
   record's `source`, so a catalog record cannot claim to be user-authored.
2. **Seven schemas had no test.** `explanationReplySchema` had none at all despite being named in
   T-02-07. All are now covered, acceptance and rejection.
3. **Nothing bound the schemas to the interfaces.** Adding a field to `Meal` would have broken
   neither `tsc` nor a test. Writing that binding immediately exposed a real divergence: the
   interfaces use `readonly` arrays and Zod infers mutable ones, so `Meal` is not assignable to
   `z.infer<typeof mealSchema>`. The runtime-relevant direction (parsed value usable as `Meal`) is
   asserted by assignment; the other direction is covered by an explicit key-set check.
4. **`ingredientSchema` had been tightened beyond TSD 3.3** to `measure: max(80)`. TheMealDB
   measures routinely exceed that, so it was a silent tripwire for P07. Restored to the spec.

## Deviations, recorded not silent

1. **Rule 2 enforcement changed.** P01's ESLint allowlist (`['*','*/*','@*/*','!zod']`) also matched
   relative imports, so the package could not import its own files. It is replaced by an I/O
   denylist plus `package.test.ts`, which asserts the manifest declares zod and nothing else. This
   is weaker against an arbitrary third-party import in source and stronger about what actually
   ships. `eslint.config.mjs` - a P01 deliverable - was edited to do it.
2. **`mealSchema` is stricter than TSD 3.3's code block**, which only sketched the refinement. The
   implemented rule is exhaustive. A strengthening, but a divergence from the literal spec.
3. **Seven symbols exist that TSD 3 does not name:** `HealthResponse`, `API_ERROR_STATUS`,
   `API_ERROR_RETRYABLE`, `kebabIdSchema`, `DATA_SOURCES`, `mealObjectSchema`, and an internal
   `httpUrl`. Each is defensible; collectively they expand the artifact every later phase pins to.
4. **URL fields are restricted to http(s)**, which TSD does not specify. `z.url()` alone accepts
   `javascript:` and `file:`, and this is where both catalog and user-authored meals are parsed.

## Known limitations carried forward

- **`CustomMeal` has no schema.** TSD 3.2 describes it as "same shape as Meal, with nutrition
  optional", but neither the TSD type nor the implementation makes it optional, and
  `ValueSchema<CustomMeal> = mealSchema` does not compile (`createdAt`/`updatedAt` are extra, and
  `strictObject` would reject them). P12 T-12-07 needs a schema per stored value and will find none.
  Raised here rather than papered over.
- **Root `node_modules/zod` is 4.6.4** (a transitive of `eslint-config-expo`) while contracts nests
  the pinned 4.5.4. Any later package importing zod without declaring it silently gets 4.6.4.
