## What the independent verification changed

The gate was green before verification and the verifier still found twelve defects. Three mattered.

1. **A single dislike could be charged twice.** `dislikedIngredients` is free user text, so
   `['mushroom', 'mushrooms']` is an ordinary thing to type. Both terms singularise to the same
   needle, both matched, and the meal was charged **-100 for one dislike** - enough to change its
   rank and, with the 0 clamp, enough to erase a meal the user would have been happy with. Needles
   are now de-duplicated after folding. Two regression tests: one term in two spellings charges
   once, and one term matching three ingredients charges once.

2. **Every contraction tail escaped the stop-word filter and silently cost the phrase bonus.**
   `normalizeText` turns an apostrophe into a space, so `"what's"` tokenises to `['what','s']`, and
   `'s'` was in no list. The stray token lengthens the query, the contiguous-run test fails, and the
   25-point phrase bonus is lost. Measured on the module's own fixtures:

   ```text
   "what is in the chicken curry"  -> Chicken Curry 51
   "what's in the chicken curry"   -> Chicken Curry 26
   ```

   This contradicted the module's own stated contract, and it degrades chat retrieval too, which
   feeds raw user questions into `queryMeals` (TSD 4.8). I probed the whole class rather than the
   one instance reported: `'d 'll 'm 're 's 't 've` **all** escaped. All seven tails are now stop
   words, with a regression test asserting the two phrasings above score identically.

3. **The second-largest weight had no point-level test at all.** Nothing asserted `diet-match`
   awards 20 or 0 - it appeared only inside a reason-ordering list. Its 0 branch is unreachable
   through `recommend`, because a diet-incompatible meal is hard-rejected first, so `scoreMeal` is
   the only way to reach it and no test did. A sign flip there would have shipped green. Three tests
   added, including the vegan-satisfies-vegetarian asymmetry.

## Other corrections

4. **A disliked term matched across a separator.** `matchedDislikedIngredients` tokenised without
   segmenting, so the term `milk chocolate` matched the ingredient `"milk, chocolate"` - the exact
   pair TSD 4.1 names as the reason `tokenizeSegments` exists. Now segmented, as the allergen module
   already was.
5. **`reading()` called a wrong number "not available".** A negative or non-finite nutrient produced
   the detail `"Calorie content not available"`, which is a false statement; PRD FR-006 is emphatic
   that "not available" means unknown. `mealSchema` guarantees an in-range integer or `null`, so the
   defensive coercion invented a state the contract forbids. Removed; `null` is the only unknown.
6. **The upper-clamp test asserted nothing.** `toBeLessThanOrEqual(100)` passes at 0, 42 and 99. The
   fixture scores exactly 100, so the test now asserts `SCORE_BOUNDS.max` exactly, beside a new
   assertion that the positive weights **sum** to `SCORE_BOUNDS.max` - which is why the upper clamp
   is unreachable by construction. If a weight ever rises, that fails where the reason is legible
   rather than silently making the clamp live.
7. **Two declared weights were dead.** `goalMatchMax` and `preparationTimeFitMax` had no reference
   outside their own declaration; the points actually awarded are the literals inside the band
   tables, so either constant could drift with nothing failing - the scattering SDD 8.2 says the
   weight object exists to prevent. Both are now pinned to their tables by test.
8. **The `WeakMap` memo comment stated a guarantee the language does not give.** It claimed "a
   mutated meal would be a different object, so a stale index can never be served". Mutation
   preserves identity; `readonly` is compile-time only. Verified by probe: rename a meal in place and
   `queryMeals` still answers for the old name. The real precondition - catalog meals are replaced,
   never edited - is now stated as a property of the callers rather than of the map.
9. **The `STOP_WORDS` test checked the wrong spelling.** Its name promised "in the form
   singularisation produces" while its body only checked the raw word, and its list contained
   `this`, which is precisely the form singularisation never produces. It also asserted nothing
   about extras, so adding a searchable word - `chicken`, say - would have made that word
   unsearchable in both the catalog screen and chat retrieval with every test still green. Now
   folded-form assertions, a no-dead-entry check, and an exact-contents assertion.
10. **A test comment described a mechanism that does not run.** The stop-words-only vector returns
    via the empty-query guard and never reaches the phrase bonus, so it does not exercise the
    `score > 0` guard as its comment claimed. Corrected, with the reason the guard is in fact
    unreachable as a discriminator recorded beside it.
11. **Coverage gaps closed.** The 125% budget boundary was proved only for `medium` (now `low` too:
    900 -> 15, 901 -> 7, 1125 -> 7, 1126 -> 0); the unknown-nutrient path only for `high-protein`
    (now all three goals - `balanced` is the trap, since its non-null path pays 7 for being outside
    the range, so a missing guard would award 7 for calories nobody knows); and the reason order is
    now compared against `SCORE_REASON_KINDS` itself rather than a re-typed literal list.

## Safety: what was checked and held

The verifier was asked specifically to break the safety rule and could not. It ran ten bypass
attempts against `recommend` - allergen by ingredient inference, by declared tag, plural and
uppercase spellings, the `wheat` -> `gluten` closure, an unknown allergy caught only by ingredient
name, and each of those again with the meal also listed as a favourite so the +10 would have to buy
its way past. Every one was rejected with `allergen-conflict` and an empty `candidates`. Rejection
runs before scoring, in the order allergen -> diet -> unavailable, and no accumulation of points can
surface a rejected meal.

## Deviations and judgements recorded

- **`RejectedMeal` is a named export TSD 4.6 does not declare.** The TSD spells the `rejected`
  element as an inline anonymous type. The named interface is structurally identical, so no caller
  written against the TSD can break, and naming it is what lets a test state its type. Kept
  deliberately, recorded here rather than silently.
- **`recommend` takes two parameters, not three.** It briefly had a `limit` with a default. TSD 4.6
  declares `recommend(context, meals)`, no consumer passed a third argument, and P03 graded exactly
  this kind of speculative widening as a defect. Removed before the gate.
- **TSD 4.6 is silent on whether the disliked-ingredient match should segment.** It says only
  `matchCount * -50`. I read it as segmenting, because TSD 4.4 segments for the same reason and the
  alternative reports a dislike the dish does not contain.
- **`matchCount` is read as distinct disliked terms, not matching ingredients.** One dislike is one
  dislike: a dish is not three times worse for naming onion three ways. The test that previously
  claimed the other reading is renamed to say which it means.
- **A single-token query always collects the 25-point phrase bonus,** because a one-token needle is
  trivially a contiguous run. That is literal TSD 4.7 step 4 and is left alone, but it means the
  phrase weight is not about phrases for the commonest query shape: a name-token hit is a fixed 35.
- **Duplicate query tokens double-count** ("chicken chicken" scores the name hit twice). TSD 4.7
  says "per query token, sum", so this is spec-literal and left alone.

## Known limitations carried forward

- **A contraction whose head is not a function word still perturbs the phrase run.** `"don't"`
  leaves `don` behind, which no word list should be asked to catch. The clean fix is apostrophe
  handling in TSD 4.1 tokenisation. **R-18.**
- **Exported constants are not frozen.** `STOP_WORDS` is a live `Set` and `GOAL_BANDS` a live
  object; `as const` and `ReadonlySet` are compile-time only. Consistent with P02-P04, so not a P05
  regression, but it is the same class as the memo comment above: a compile-time promise standing in
  for a runtime one.
- **`BUDGET_BAND_MAX_CENTS.high * 5` exceeds `Number.MAX_SAFE_INTEGER`.** Unreachable, because any
  price at or below the ceiling takes the first branch. Cosmetic.
