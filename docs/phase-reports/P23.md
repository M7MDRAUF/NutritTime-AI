## 1. The audit that reopened the phase

The phase had been reported as largely done. A read-only auditor ruled it **2 MET · 3 PARTIAL ·
2 NOT MET** and was right on every contested row. Two rulings mattered most:

- **T-23-05's focus half had no coverage at all.** `document.activeElement` appeared **nowhere** in
  `apps/` or `e2e/` — verified by search, twice, independently. A form that dumped focus to the top
  of the document on a failed submit would have passed the entire suite.
- **T-23-06's "nothing to respect" was false.** `AssistantScreen.tsx` passes `loading={pending}` and
  `AccessibleButton.tsx` renders an `ActivityIndicator` on it — a spinner running to the **30 s**
  chat budget — and nothing in the app read `isReduceMotionEnabled`.

**And the same auditor found 21 unapplied `NEEDS-INTEGRATION` items across the window's reports**,
14 documentation and **7 code**, where the orchestrator's own ledger had six. That is the P16–P18
failure mode at seven times the scale, and its cause was a ledger kept in the coordinator's head
rather than in a file. It is a file now, checked independently.

## 2. T-23-05 — both halves, with a negative control

**Focus.** `document.activeElement` went from zero occurrences to two tests asserting the focused
**input node** — identity, not just presence, so a remount-plus-refocus mutant fails. Probes:
blurring on a refused Save gives `expected <body><div>…</div></body> to be <input maxlength="200" …>`;
keying the form by attempt number gives the same; and `FormField` focusing its own field lands on
`field-minutes`.

**Announcement.** `announceOnMount` added to four silent notices across two forms, following
`HomeScreen.tsx`'s existing fix rather than inventing a second mechanism. Four probes each redden one
test with `expected null to be 'alert'`, and a fifth — _every_ `StatusMessage` announces — reddens
the deliberately-silent control. **No single constant satisfies both**, which is the pair this
project requires after P16's all-null nutrition case passed the very mutation it existed to catch.

**A count I relayed was wrong, and the agent measured it.** I passed on "a failed Save mounts **five**
`aria-live="assertive"` alerts". It is **four** — `[4, 4, 0, 0]` — because `FieldErrors`' fifth
member `allergies` cannot fail through the UI at all, per its own validator's docstring. And **none**
of the three notices being added mounts in that state, and all three are `polite`, so they never join
the flood. Now a test.

## 3. T-23-06 — the mechanism, and an environment that made the test impossible in one direction

Carried by a `useReducedMotion()` hook — `AccessibilityInfo.isReduceMotionEnabled()` plus its
`reduceMotionChanged` event — **not** by a new prop: `TSD.md` §6.7 fixes `AccessibleButton`'s props
at nine, so a tenth is the same document amendment as R-56, and the `ThemeProvider` route is filed
instead. Under reduce-motion the spinner becomes a still `clock` mark in the same slot.
`animating={false}` was rejected because it is **not portable** — Android's
`ProgressBarContainerView.kt` sets the view `INVISIBLE`.

**Both directions asserted in one file**: spinner 1 / mark 0 against spinner 0 / mark 1, with
`always-spin` and `always-still` reddening opposite halves. A single-direction assertion would be
satisfied by a component that ignores the setting and always does the reduced thing.

**And jsdom 30.0.1 has no `matchMedia`** — measured, not assumed — so react-native-web fail-closes to
`true` and the motion direction was **untestable** until the test supplied the query itself. That is
BRIEF §6.1k exactly as written: a line that cannot execute in the environment you measured it in.

## 4. PRD §10.1's thresholds were missing from the assistant entirely

Found by the reliability lane, not the accessibility lane: **`useAssistant.ts` and
`AssistantTurnRow.tsx` implemented neither of §10.1's loading thresholds.** The constants existed in
exactly one place — `features/home/useRecommendations.ts` — so a cold question showed **one static
sentence for up to the full 30 s budget**, with no escalation.

Built: nothing below 200 ms, the retrieval sentence at 200 ms, the model sentence at 2 s, terminal,
and reset for the next question. The constants are **imported**, not copied — three copies of a
mapping with two already diverged is a defect this project already has on record. The figures are
hand-transcribed in the test, because importing them and advancing by them would compare the
constant to itself (§6.1g), which is the answer `Home.dom.test.tsx` had already worked out and is
cited rather than re-derived.

**Escalation composes with reduced motion:** the escalation is _text_, so it survives reduce-motion
intact — asserted in one render. A user who asked for less motion still learns the request moved from
"sent" to "the model is warming up".

## 5. R-70's structural half, closed

One of the new strings had been written outside `assistantCopy.ts` and so outside the denied-claim
sweep. The string was the symptom; **the defect was that the sweep was hand-listed**, which makes
every future string opt-in to the guard that exists because _a guard aimed at one source of text does
not cover another_. P20's CRITICAL was exactly that: a server copy string reading _"allergen free"_
that failed **0 of 824** tests.

The string moved into the module and the sweep now **walks** both copy objects. Probe: a denied claim
in a **brand-new key** reddens it — `"claim": "allergen free"` — where the old list enumerated keys
by name and had no name to reach it by. The count assertion was kept, because a walk that silently
found nothing would otherwise pass every "no denied claim" check vacuously — T-19-09's lesson on the
other axis.

## 6. A false library claim in six files, four still asserting it

_"react-native-web 0.21 maps neither from the other"_ is **false**: 0.21.2 maps
`accessibilityLiveRegion` to `aria-live`, with `'none'` → `'off'`
(`dist/modules/createDOMProps/index.js:460-462`). Six files carried the claim; four still asserted
it, and **two of those four are test files**, which no production fix reaches — a test asserting a
**retracted** rationale is worse than a bare wrong comment, because the reader who opens the test to
understand the component gets the withdrawn reason with no sign it was withdrawn.

**The strongest verification in the window belongs here:** one agent falsified the claim by a **test
failure** — a first-draft assertion expecting no `aria-live` reddened with
`expected 'off' to be null` — rather than by reading `node_modules`. And one file's version of the
claim is **TRUE** and was correctly left off the fix list.

## 7. Judgements recorded rather than quietly decided

- **X-47 — an error summary that takes focus is both permitted and forbidden by one Plan line.**
  _"Preserved on validation failure; moved deliberately, never on every blur."_ A summary receiving
  focus after an invalid Save is a deliberate move **on validation failure**. The agent owning both
  forms **raised a stop condition and did not build it**, which is correct. Two agents reached
  different conclusions on different axes and both are right: one that "nothing forbids it"
  (architecturally true — unlike the streaming animations, no document makes it impossible), one that
  it contradicts the Plan (policy true). **The two forms cannot both be right as they stand**:
  `MealFormScreen` has summary and focus move, `DietarySetupScreen` has neither.
- **`Plan.md` mis-cites PRD §10.5 for reduced motion**, and so did `primitive.ts` and
  `playwright.config.ts`. §10.5's bullets are roles and labels, touch targets and text scaling —
  motion is absent. The real adoption is the generator's pre-delivery checklist. This is the same
  mechanism as `PRD §15.5`, which did not exist and reached 18 files: **a plausible section number,
  cited with confidence, never opened.** The code comments now quote the checklist text instead of
  citing a line, because the same citation drifted **three times in one session** as register rows
  were inserted above it.
- **R-55's row carried two false clauses** — "four groups across two screens" (it is three groups on
  one) and, worse, its _justification_: the claim that the fix would change accessible names an
  existing suite asserts. Measured, deleting `selected` outright left **15 passed / 0 failed**. The
  property was both invisible to the user and unpinned by the suite, which is how it survived nine
  phases. It was still right to give it a gate — for the opposite reason to the one recorded.
