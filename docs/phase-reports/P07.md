## The number this phase must be judged on

**Nutrition derives for 5 of 60 records. The other 55 carry four `null`s and a recorded reason.**

That is the all-or-nothing rule of TSD 7.4 working exactly as written - no partial sums, no
substituted averages, no meal showing `0` where it means unknown - but it is a thin result and it
would be dishonest to file it as a success. Two causes, and only one of them is fixable by effort:

1. **The binding table reaches 119 of the catalog's 351 distinct ingredient names.** Each binding is
   a deliberate choice against the real archive; they cannot be generated. The naive token-overlap
   matcher this replaced proposed `Bacon` -> _Bacon, meatless_, `Chicken` -> _Fat, chicken_,
   `Whole Milk` -> _Cheese, ricotta_ and `Flour` -> _Potato flour_. That is the near-miss failure
   T-07-07 forbids, and it produces wrong nutrition that looks right.
2. **FNDDS has no row at all for rosemary, mint, saffron, cardamom, allspice, bay leaf, garam
   masala, fenugreek, shallots, toor dal, ghee, celeriac - or plain wheat flour.** It is a food-
   consumption survey table, not a culinary one. Under all-or-nothing, one bay leaf blanks an entire
   meal, and no amount of binding work changes that.

`catalog.test.ts` asserts the derived count is **exactly 5**, not "at least 3". A floor cannot tell 5
from 3 and would stay green while coverage regressed. The number moves only deliberately.

**A dedicated catalog-coverage pass is scheduled after P18** (plan section 7). Raising coverage means
authoring densities and countable gram weights that nothing downstream can check (R-03), so sparse
and refusing beats dense and wrong.

## What the hand review found (T-07-04)

`docs/catalog-allergen-review.md` records the review of **all sixty records** - including the
fifty-three that needed no change, because an unrecorded "no change" is indistinguishable from an
unreviewed record. Five corrections, every one a false negative:

| Record                             | Added    | Why inference missed it                                                                               |
| ---------------------------------- | -------- | ----------------------------------------------------------------------------------------------------- |
| `roasted-eggplant-with-tahini-...` | `sesame` | Tahini is in the dish's own title and absent from its ingredient list                                 |
| `spinach-ricotta-cannelloni`       | `wheat`  | The pasta is only in the NAME; the ingredients say "Cannellini Beans" - one letter away, and a legume |
| `chilli-prawn-linguine`            | `milk`   | "Fromage Frais" reached no dairy token                                                                |
| `christmas-pudding-flapjack`       | `wheat`  | Christmas pudding arrives as one compound word carrying no wheat token                                |
| `beef-wellington`                  | `milk`   | Retail puff pastry is butter-based; the dish has no other dairy                                       |

The `fromage frais` miss was a gap in the shared lexicon, not just this record: `fromage`, `paneer`,
`halloumi` and `quark` were added to `allergen-lexicon.ts` and shipped with P06. **R-19** records that
the lexicon is incomplete by construction and that this review, not a longer word list, is the real
control.

One derived tag was deliberately **kept** although it is probably wrong: `chicken-enchilada-casserole`
carries wheat from "corn tortillas". Removing it would expose a coeliac if any tortilla in the dish
is a wheat blend; keeping it only hides a safe meal. The tolerable error runs one way.

## Defects found and fixed in this phase

1. **A catastrophic measure misread I introduced myself.** The sized-container pattern I added for
   `3 400g cans` also matched `400g` as 4 x 00 and converted it to **zero grams** - silently, on the
   commonest measure in the catalog. The separator is now required, and a test pins `400g -> 400`
   beside `3 400g cans -> 1200`.
2. **Two tests encoded premises the real data contradicts.** `tblsp` was treated as a typo to refuse;
   it is how TheMealDB spells a tablespoon (`"2 tblsp"`, `"3 tblsp chopped"` are both live). And
   `1 cup chopped` was refused as an unverifiable unit; the preparation word qualifies the food, not
   the amount, so refusing discarded real measures across most of the catalog for no accuracy gain.
   Both corrected with the reasoning recorded.
3. **A single-word preparation unit was not stripped.** `1 chopped` and `2 sliced` left `chopped`
   standing as an unrecognised unit, failing measures that plainly say "one onion".
4. **`no-console` had to be exempted for the seed script**, which is a hand-run CLI whose entire user
   interface is its output. The rule is **restated minus `log`** rather than switched off, because
   P01 learned that an `'off'` exemption silently drops the whole rule.

## Divergences recorded, not resolved unilaterally

- **X-15 - `fdcId` cannot be `string`.** TSD 7.4 declares it non-null. Measured: **44 of the
  archive's 1,882 ingredients publish no FDC ID on any macro**, including olive oil, unsalted butter
  and the canola, corn, peanut and soybean oils. Implemented as `string | null`; `usdaCode` keeps the
  row traceable and `sourceLabel` keeps its provenance. TSD 7.4 should be amended to match the data.
- **X-16 - the catalog package graph.** TSD 2.3 says `catalog -> (nothing)`; TSD 7.4 step 1 mandates
  using 4.1's text primitives, which live in the domain. Resolved toward 7.4, the more specific
  instruction. **The edge is build-time only**: `src/index.ts` imports nothing from `src/seed/`, so
  nothing reaching a device or a request path carries it.
- **The nutritionally-inert rule.** An ingredient whose four per-100 g macros are all exactly zero
  (salt, water) survives an unparseable measure. This is a consequence of all-or-nothing, not an
  exception to it: any mass times zero is zero, so the totals are provably independent of the
  quantity the measure failed to state, and reporting them is exact rather than estimated. The test
  is on the DATA, so it can never be claimed for a food that contributes something - a single
  non-zero macro fails. "Salt - to taste" appears throughout the catalog.
