## 3. Two rulings the documents did not settle

### The 12 s budget bounds the explanation STEP, not each meal

Three sequential explanations at 12 s each is 36 s, against TSD §6.5's 15 s client deadline. The
agent invented no whole-request budget and stopped, which was right.

**The resolution invents nothing.** Every row of PRD §10.1's table is a **whole-path** budget — app
start to usable Home, local navigation, recommendations without AI, recommendation explanation,
assistant answer. The explanation row reads "warm model ~5 s, hard timeout 12 s", **singular**,
among per-path figures. So the budget bounds the explanation step of one request and three
sequential calls **share** it.

Warm, that yields three model-written explanations in ~5 s where a fan-out would yield one,
deterministically. And when the budget is spent the remaining meals take template text **with no
provider call** — PRD FR-009's degradation happening _within a single response_.

Recorded as a reading of PRD §10.1, not a figure the orchestrator supplied. If the user disagrees,
the alternative is a new whole-request budget in a document.

### A two-condition gate split across two owners pinned neither half

TSD §5.4: "Explanations are attempted only when `aiEnabled` is true **and** `AI_ENABLED` is true."
Two agents each implemented it in their own module, so **removing the route's half left all 45 tests
green.** Defence in depth that made neither layer provable.

Both kept, both pinned. The route's check has an observable consequence the lane's does not: when
either condition is false, `explainRecommendation` is **never called at all**, so a
`vi.mock(..., { spy: true })` asserting zero calls sees the difference. Remove the route's check and
the spy reddens; remove the lane's and its own test reddens. The route is named primary, because
§5.4 places the gate there and only the route knows the _request's_ `aiEnabled`.

## 4. What the audits found that the gate did not

### One CRITICAL — containment's threat model covered the model and not the server

`ai/chatCopy.ts`'s three user-facing strings were asserted only as `toBe(CHAT_COPY.x)` — a constant
compared to itself — and the one non-circular guard was a five-alternative regex against
`DENIED_CLAIMS`' 22 phrases. So rewriting `greeting` to

> `'Hello. Every meal I can show you is allergen free.'`

failed **0 of 824 tests**. A peanut-allergic user asking "what can you do?" would have read that
every meal is allergen free — from the server's own copy, with no model involved.

**And `chat.integration.test.ts:438` asserts that a _model_ emitting that same phrase gets a 503.**
The identical sentence was forbidden from the model and permitted from us.

Closed by running every user-facing string, and every `copyForUnresolved` reason, through
**`deniedClaimIn` itself** — the same function containment uses, an independent authority covering
all 22 phrases by construction. Reason-list completeness is a compile error via
`satisfies Record<UnresolvedReason, true>`. Measured after: the mutation now fails exactly 2, both
in the new file, while the pre-existing regex stays green — which is the proof it catches what the
regex cannot. Recorded as **R-70**, with the general lesson rather than the instance: a guard aimed
at one source of text does not cover another.

### Four MAJORs, and in every one the production code was already correct

| Finding                                 | Measured before              | What was missing                                                                     |
| --------------------------------------- | ---------------------------- | ------------------------------------------------------------------------------------ |
| `outcome.ts`'s abort mapping unasserted | `→ 'ok'` failed **0 of 136** | The module was extracted and shipped **with no test at all**                         |
| `app.ts`'s recommendations `sink`       | **0 of 824**                 | Every explanation log test mounts its own express app; none goes through `createApp` |
| All eight RULES clauses deletable       | **0 of 824**                 | Prompt asserted structurally, never by content                                       |
| `durationMs: 0`                         | **0 of 824**                 | Every test froze the clock, so a computed zero and a constant are indistinguishable  |

In each case the fix was a test. `explanation.ts`, `recommendations.ts` and `app.ts` are behaviourally
unchanged by all four repairs.

### The lesson worth more than the four fixes

The `outcome.ts` finding exposed a distinction this project had been blurring. A test had written
`fellBack(outcomeForFailure(error))` — **computing its expectation by calling the function under
test** — and the orchestrator praised that as the derive-don't-restate discipline.

**It is the opposite, and the difference is the authority.** Reading bounds out of
`chatModelReplySchema` pins a module against a _different_ source, so a drift in either fails the
other. Reading from _the subject_ restates the implementation in test syntax. Both look like "don't
retype the constant" and only one is a test. Now BRIEF §6.1g.

And the value left unpinned was `OllamaAbortError` — **exactly the one three copies of that mapping
had already diverged on.**

## 5. Three copies of one mapping, two already diverged

The failure-to-outcome mapping was written by the chat route, transcribed by hand into the
recommendations route, and written a **third** time inside the explanation lane. The third
**already disagreed** on `OllamaAbortError`: `undefined` in one, `'unreachable'` in another.

Nothing could have caught it. Each route's tests assert its own lines against its own expectations,
so there is **no assertion any of the three suites could make about a constant in a file it does not
import**.

A divergence test was the obvious repair and it was unavailable. `ai/outcome.ts` holds the single
copy, and **one copy makes the divergence unrepresentable** — which is better than a test that
notices it. Three independent authors reached for the same collapse, which says the distinction is
hard to hold rather than that anyone was careless.

## 6. Probes

Every probe was run **one mutation per run** (BRIEF §6.1a, adopted after batched runs gave
inconsistent failure _totals_ in P19), restored, and hash-verified. The evidence in this report is
the **failing test names and the assertion messages**, not counts.

Two worth quoting for their specificity:

- deleting the no-safety-claim clause reddens **exactly 3** — its two obligations plus the count —
  and leaves the other nine green. Each clause has its own oracle and none shields another;
- `durationMs` as a wall-clock total rather than a per-call slice yields
  `expected [ 1000, 2000, 3000 ] to strictly equal [ 1000, 1000, 1000 ]`, so the assertion catches a
  **wrong** duration and not merely a zero.
